## 1. 智谱"完全自训练"三维定义（核心锚点）

### 1.1 公告原文定义 [公告事实]
HKEX 公告（北京智谱华章科技股份有限公司，股份代号 2513，公告日期 2026-09-13）"释义"节对术语的原文界定：

> **「完全自訓練（Fully Self Training）」指 本集團的技術願景，即下一代 GLM 模型將在上一代 GLM 所搭建的環境裡訓練，形成遞歸式自我改進（Recursive Self-Improvement）閉環，涵蓋數據自產、環境自造、基礎設施自我優化三個維度。**

即官方把"完全自训练"拆成**三个正交维度**：

| 维度 | 公告原文要点 [公告事实] | UDOS 对应线 |
|---|---|---|
| **数据自产**（数据自生成） | 「通过模型间自我对弈、规则校验、执行验证、模型评审及人工抽检等方式生成、筛选及积累高质量数据……持续回流至预训练、中训练及后训练阶段」 | **v4.2 线**（self_train.py，已落地） |
| **环境自造**（任务环境自生成） | 「由智能体采集和转化真实任务、试做任务、生成验证器及检查任务可解性的技术流程……任务环境能够成为可规模化生产及复用的训练资源」 | **v4.1 线**（curriculum.py + SolvabilityVerifier，已落地） |
| **基础设施自我优化** | 「利用模型在编码及系统工程方面的能力，协助开发和优化训练及推理系统的**算子、内核、调度、缓存及服务栈**，使模型能够逐步参与支撑其自身迭代的基础设施升级」 | **v4.3 线（本线）** |

### 1.2 本线定位 [推断]
v4.3 是三维飞轮的**收口与第三维（基础设施自我优化）的缩微类比**：
- v4.1 解决"任务/课程从哪来"（环境自造）；
- v4.2 解决"训练样本从哪来、如何治理、是否真改进"（数据自产，且诚实记录了 teacher→student 崩塌与自产数据 A/B 落败）；
- v4.3 解决"**系统配置/服务栈参数谁来调**"——把 batch/chunk/缓存/集成权重/控制频率/码本规模当作"基础设施配置"，做**自动搜索—验证—选用**，并把三维串成一个自进化 orchestrator。

这是"基础设施自我优化"在 CPU 合成低维玩具里的**类比实现**：真实系统优化算子/内核/调度，UDOS 优化的是 `BatchPredictor.max_shard`、`InferenceCache`、`DeepEnsemble` 权重、`HierarchicalController` 频率、`ChangeMaskVQ` 码本规模等**等价物**。

## 3. RSI（递归自我改进）概念对齐

### 3.1 定义 [媒体陈述 + 共识]
- RSI（Recursive Self-Improvement，递归自我改进 / 自进化）指"AI 系统改进**自身改进能力本身**"的正反馈闭环：每一轮自我修改都让下一轮更强，区别于"人类迭代 AI"。 [媒体陈述：Data Science Dojo 2026-07-15；MindStudio；aiwiki]
- 关键辨析（与本线纪律直接相关）：**当下真实运行的 RSI 例子都是"有界"的**——agent 改写代码、优化训练、给自己出更难任务；**没有任何一个是端到端重设计自身权重**。 [媒体陈述：Data Science Dojo]
- 一篇 2026 年 arXiv 文章把 RSI 表述为"AI–研发系统"的属性而非单一模型属性，并强调"自我修改 S₀→S₁→S₂…在给定目标上单调改进"需要内省阈值。 [媒体陈述：arXiv 2607.04277；2609.00137]

### 3.2 对 UDOS 的映射 [推断]
- UDOS 不做"端到端重设计主权重"——主预测器全程**冻结只读**（eval_mse 锚点 0.045556，主参恒 52191）。这与"真实 RSI 目前都有界"的共识一致。
- UDOS 的"自进化"是**外挂、纯前向、零梯度**的元层：搜索器调配置、orchestrator 串课程→数据→配置、多代曲线诚实记录"真改进 vs 退化"。**不假设飞轮必然上升**（历史教训：teacher→student 10.21x 崩塌、自产数据 A/B 17x 落败均已 REJECT/opt-in）。

## 4. 与 AI-Scientist / ShinkaEvolve / 世界模型自产数据的关系

### 4.1 The AI Scientist（Sakana AI） [媒体陈述，arXiv 可核]
- 论文《The AI Scientist: Towards Fully Automated Open-Ended Scientific Discovery》，arXiv **2408.06292**（2024）；其后发表于《Nature》（Sakana 官方 2026-03-26 公告）。
- 流程：生成研究想法→检索文献→**写代码、跑实验**→出图写注释→写整篇论文→模拟评审；可开放式迭代，想法进不断增长的 archive。
- v2 用 **Best-First Tree Search（BFTS）** 在实验分支上做树搜索，像象棋引擎一样把算力集中在最有希望的路径、剪枝失败分支。 [媒体陈述：多个二手分析，2026]
- **UDOS 类比** [推断]：v4.3 的"搜索—验证—选用闭环"（dev1）与 BFTS 同构——小规模网格/随机搜索一批配置候选，按同一合同评分，保留优者、剪枝劣者；但 UDOS 是**确定性、低维、CPU** 的玩具版，不做真实文献检索与论文写作。

### 4.2 ShinkaEvolve（Sakana AI） [媒体陈述，arXiv 可核]
- 论文《SHINKA EVOLVE: Towards Open-Ended And Sample-Efficient Program Evolution》，arXiv **2509.19349**（2025-09）。
- 三个关键技术：①平衡探索/利用的父代采样；②**代码新颖性拒绝采样**（novelty rejection-sampling）高效探索搜索空间；③**基于 bandit 的 LLM 集成选择**。
- 报告指标（**按其自述，非本工程复算**）：circle-packing 用约 **150 个样本**找到新 SOTA；并产出可提升 MoE 的负载均衡 loss。 [媒体陈述]
- **UDOS 类比** [推断]：
  - "bandit-based ensemble selection" ↔ UDOS 4.3.0 搜索器里**集成权重**这一搜索维度（`DeepEnsemble` 成员权重）；
  - "样本高效" ↔ UDOS 坚持**小规模网格**搜索、每候选都过同一验证合同，不烧算力；
  - "novelty rejection" ↔ dev2 候选账本里对"被反证/无收益"配置**拒绝落地、留档**，而非盲目采纳。
  - 注意：UDOS 不调用 LLM 做变异算子，也不复现 circle-packing；仅取"保留 archive、择优、样本高效"的骨架。

### 4.3 世界模型自产数据 [推断 + 工程已有]
- 思想脉络（World Models / Dreamer 一脉，用学到的环境模型在"想象"中 rollout 出训练样本）：UDOS v4.2 已用 `LatentWorldModel.encode_latent→transit_step→decode_latent` 想象 (s,a,s') 三元组，并配 `ConservationChecker` / `ExecutionValidator` / `ModelReviewer` 做守恒/可执行/不确定性三道筛。
- 这正是公告"数据自生成：自我对弈→规则校验→执行验证→模型评审→人工抽检→回流"的逐环缩微。v4.3 不再新增数据机制，而是把这条已验证的管线（含诚实的 REJECT 记录）作为 orchestrator 的一环。

### 4.4 三者与本线的关系一句话 [推断]
AI-Scientist 给"**开放式树搜索 + 评审**"范式；ShinkaEvolve 给"**archive + 样本高效 + bandit 选优**"范式；世界模型给"**想象自产数据**"范式。v4.3 把三者压成一个 CPU 玩具：**配置空间做树/随机搜索（BFTS 骨）、候选留 archive 账本（Shinka 骨）、课程→数据→配置串成递归环（RSI 骨），全程冻结主权重、诚实记退化**。

## 6. 诚实结论与边界

3. **两项市场说法 [UNVERIFIED]**："1GW 国产算力""收购中科加禾"在本可核附件中**查无实据**，工程文档不采信。
4. **RSI 边界**：真实世界 RSI 目前都"有界"、无一端到端重设计权重；UDOS 与之对齐——冻结主预测器，外挂零梯度，不宣称飞轮必然上升。
5. **绝不编造**：本文未给出任何本工程未实测的指标；所有数字性结论须由 `benchmarks/results/*.json` 真实落盘后回填。
