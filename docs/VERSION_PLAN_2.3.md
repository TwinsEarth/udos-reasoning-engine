# UDOS 版本规划与设计：2.2.1 → 2.3.0 → 2.3.1

本文件是 2.3.x 的设计基线（design contract）：先锁问题（均来自 2.2.1 实测）、
可检验假设、同合同 A/B 口径、兼容锚点、发布门禁与回滚。预期改善在跑出结果前都只是
假设，不写成结论。吸取 2.2 的教训：**优先确定性、不依赖训练种子的稳健机制**。

## 1. 出发点：v2.2.1 的两个实测短板（证据 `VERIFICATION_v2.2.1.md`）

| 编号 | 2.2.1 已观察到的事实 | 2.3 处理 |
|---|---|---|
| C1 | CTM certainty **未校准**：置信分层非单调，最高置信档误差反而更高（高/低档误差比 1.80） | **F1 保序回归校准 + 回归 ECE/可靠性**（确定性后处理） |
| C2 | 自由 rollout 误差累积（growth 2.49×）；多步损失 `_step_weights=linspace(1,0.5)` 对**远期步欠加权**；SS 已证收益随种子不稳 | **F2 多时域均衡损失**（无自喂噪声的稳健杠杆）+ **F3 经验预测区间** |
| C3 | 校准结果/多 checkpoint 不能在线管理 | **F4 `/calibrate`、`/checkpoints`、`/load`** |
| G5 | 数据仍为合成 | 沙箱边界，不处理 |
| G6 | 无 docker daemon | 环境边界，进程等价验证 |

## 2. 版本切分
- **2.3.0（minor）**：F1 置信校准、F2 时域均衡损失、F3 split-conformal 经验预测区间、
  F4 校准/模型管理接口；全部向后兼容（新参数默认等价 2.2.1）。
- **2.3.1（patch）**：实测暴露的边界修复、版本/文档对齐、QA 收口后发布，对外版本 2.3.1。

## 3. F1 置信度校准（核心，确定性）

### 3.1 方法
certainty 是「1−归一化同步熵」，非分类概率；输出是连续回归。故采用**回归校准**：
1. 在校准集前向，取每样本原始置信 c=certs[:,1,-1] 与逐样本误差 e=mean((ŷ-y)^2)；
2. 以校准集误差均值把误差映射为同域「经验精度」 a=exp(−e/s)，s=校准集 e 的均值（记录，
   保证 a∈(0,1] 且与 c 同尺度）；
3. 对 (c,a) 拟合**保序回归（PAVA，自实现、零依赖）**，得到单调非降阶梯映射
   g:c→校准置信；持久化其断点，供推理与 checkpoint 复用。

### 3.2 可检验假设 H1 与判据
- 回归 ECE：K=5 等频桶，ECE=Σ (n_k/n)|acc_k−conf_k|，分别对**校准前 c** 与**校准后 g(c)**
  计算；并算校准置信与误差的 Spearman 秩相关 ρ（期望 <0，置信越高误差越低）。
- **H1（确定性、应稳健）**：校准后 ECE 较校准前下降（且不为 0 的平凡作弊），ρ_calib≤ρ_raw。
  保序拟合在校准集天然降 ECE，故判据要求在**独立测试集**上 ECE 也下降（防过拟合），且
  断点非退化（>1 段、非恒定）。不达标则如实报告、不对外宣称已校准。

## 4. F2 多时域均衡损失（无随机性的长时程杠杆）
- `TrainConfig.step_weight_scheme: "front"(默认=linspace(1,0.5)，逐位复现 2.2.1)/
  "uniform"(等权)/"back"(linspace(0.5,1)，远期加权)`；`_step_weights` 按方案生成。
- **H2**：同合同配对（同种子/数据/初始 state_dict，仅方案不同）下，远期权重更高的方案
  是否稳健降低 rollout 后段 MSE/growth 且不损单步。
- **裁决（两组同合同实验，结论为"口径敏感、不稳健"，脚本可复现）**：
  - 口径A（无早停/45ep/种子 1000+·2000+/n32，`ablation_horizon_weight.py`）：uniform 远期
    tail **3/3 种子低于 front（均值 −60.2%）**、单步也更低，初看应设默认；
  - 口径B（早停/60ep/train seed42/独立 seed2718/n48，即正式 build 口径，
    `sensitivity_step_weight_pipeline.py`）：**front 反超**（uniform 单步 +50%、tail +29%）。
  - 跨口径方向不一致 => 与 v2.2 SS 同类：权重方案优劣对数据划分/早停口径敏感，证据不足以
    授权改默认。**最终默认保持 front（逐位复现 2.2.1），uniform/back 均为 opt-in**，正反结果
    全部留档，不宣称 uniform 有稳健增益。本代可靠增益来自不依赖训练种子的 F1/F3。

## 5. F3 split-conformal 经验预测区间
- 校准集对每步 h 统计自由 rollout 残差的分位幅度 q_h（如 5%/95%），推理时
  `predict_interval` 返回中值预测 + 每步区间；属 split-conformal 简化（交换性依赖校准/测试
  同分布），诚实标注非严格分布外保证。
- **H3**：在同分布独立测试集，90% 名义区间经验覆盖率落入合理带（约 ≥85%），且区间宽度随
  horizon 单调不减（与误差累积一致）。

## 6. F4 服务/持久化
- `POST /calibrate`：对挂载预测器在新鲜校准集拟合 CalibrationModel（返回校准前/后 ECE），
  挂到预测器并随 `/save` 持久化；未训练 409。
- `GET /checkpoints`：列出 checkpoints/ 下件（名/字节/mtime/版本）；`POST /load` 按白名单
  名加载（含校准器）并挂载。
- persistence bundle 增加可选 `calibration`（旧档无此键按未校准处理，向后兼容）。

## 7. 向后兼容锚点（逐条有测试）
1. `step_weight_scheme="front"` 时 `_step_weights` 与 2.2.1 逐元素相同，默认训练等价。
2. 无 calibration 时 evaluate/reason 行为与 2.2.1 一致；evaluate 旧键全部保留、只新增键。
3. 旧 checkpoint（无 calibration 键）可正常 load；2.2.1 的 77 测试原样全绿。
4. 版本三处单一来源同步 2.3.1；服务旧路由字段不删不改语义。

## 8. 发布门禁
- 77 旧测试 + 新增测试全绿；核心覆盖率不低于 2.2.1 量级；`--guard` 通过；冒烟全过。
- H1 在独立测试集成立（确定性，必须复现）；H2/H3 多种子证据落基准 JSON，结论按证据强度措辞。
- 从交付 zip 全新解压独立跑通 build 脚本；版本三处一致 2.3.1。

## 9. 回滚
- 校准器为外挂后处理，移除即回到 2.2.1；step_weight 默认 front 即完全回退；区间为只读附加。
- 任何新接口异常不影响既有路由（分层异常 → 409/400/500，进程不崩）。
